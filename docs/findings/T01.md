# T01 spike findings

Date: 2026-09-13. Host: Omarchy 4.0.2, Quickshell 0.3.1, Hyprland 0.56.2 (Lua
config), herdr 0.8.2 (socket protocol 20). The spike was a throwaway service
plugin (`nytafar.gjetr-spike`) symlinked into `~/.config/omarchy/plugins/`,
enabled, observed, then disabled and removed. Its code is not kept.

## 1. `events.subscribe` from QML: works

A `Quickshell.Io.Socket` with a `SplitParser` received the full stream inside
the live shell.

- `session.snapshot` over a one-shot `Socket` returned a single 31 KB line with
  20 agents; `SplitParser` handled it. The socket then reports error code `1`
  (peer closed) and `connected=false`. That is the normal end of a one-shot
  request, not a failure.
- The subscription reply is the first line:
  `{"id":"sub","result":{"type":"subscription_started"}}`. Events follow as
  `{"event":"pane_updated","data":{"type":"pane_updated","pane":{...}}}`.
  Note the naming split: subscription **types** are dotted
  (`pane.updated`), event **names** on the wire are underscored
  (`pane_updated`), and `data.type` repeats the underscored name.
- Parse-stage errors come back as `{"id":"","error":{...}}`, so matching on the
  first reply line, not the id, is required (confirmed).
- **Subscription scoping.** In the schema, `pane.agent_status_changed` and
  `pane.scroll_changed` require a `pane_id`, and `pane.output_matched` requires
  `pane_id`, `match` and `source`. Subscribing to one of these without its
  fields fails the whole request with
  `invalid_request: missing field 'pane_id'`. Every `workspace.*`, `tab.*`,
  `worktree.*` and `layout.updated` type is global, and so are the remaining
  `pane.*` types, including `pane.updated` and `pane.agent_detected`.
- `pane_updated` carries a full `PaneInfo` (`agent`, `agent_status`,
  `terminal_title`, `terminal_title_stripped`, `label`, `cwd`,
  `foreground_cwd`, `revision`, `scroll`, ...). The global stream alone can
  therefore track status. Per-pane `pane.agent_status_changed` requires
  resubscribing whenever the agent set changes.
- **Volume.** While herdr was active, the stream carried about 20 lines per
  second in batches about 100 ms apart, which works out to roughly one
  `pane_focused` + `tab_focused` + `workspace_focused` group plus
  `pane_updated` per tick. It is bursty: the QML counter later sat at 131 lines
  for 10+ seconds with nothing new. Collapsing has to cover focus churn, not
  only `revision` bumps.
- **No replay on subscribe.** Two back-to-back probes timed every line from
  connect. Lines arrived evenly at about 100 ms spacing, and only 15 fell in the
  first 300 ms. There is no burst of historical events, so the snapshot is the
  only source of initial state.
- Not observed: a live `pane_agent_status_changed` line. All agents stayed
  `idle` during the spike, and I did not prompt agents to force one. Its shape
  comes from the schema (`pane_id`, `workspace_id`, `agent_status`, optional
  `agent`, `display_agent`, `title`, `state_labels`).

## 2. Bottom-layer, no-focus `PanelWindow` on `HDMI-A-2`: works

The spike used `anchors` on all four edges,
`exclusionMode: ExclusionMode.Ignore`, `WlrLayershell.layer: WlrLayer.Bottom`
and `WlrLayershell.keyboardFocus: WlrKeyboardFocus.None`, with `screen` taken
from a `Variants` over `Quickshell.screens` filtered on `name === "HDMI-A-2"`.

- `hyprctl layers` showed `gjetr-spike` 1024x600 at level 1 (bottom), between
  `omarchy-background` (level 0) and `omarchy-bar` (level 2, 28x600 at the
  right edge). `grim -o HDMI-A-2` showed the surface rendering.
- The window reports `100x100`, then `0x0`, before settling at `1024x600` on
  the first configure. Layout code must tolerate zero size transiently.
- Keyboard focus stayed on the main monitor's window (`hyprctl activewindow`
  unchanged, `DP-1` still focused).
- Bar inset: `HDMI-A-2` reports `reserved: [0, 0, 28, 0]`, which is the bar
  on the right (`shell.json` `bar.position: "right"`, `Style.bar.sizeVertical`
  28). An `Ignore` surface spans under it, so gjetr must inset content itself.

## 3. Runtime rotation: works, via `hyprctl eval`

- `hyprctl keyword monitor HDMI-A-2,preferred,auto,1,transform,1` is refused
  under the Lua config: `keyword can't work with non-legacy parsers. Use eval.`
- This works, without editing `monitors.lua`:

  ```bash
  hyprctl eval 'hl.monitor({ output = "HDMI-A-2", mode = "preferred", position = "auto", scale = 1, transform = 1 })'
  ```

  `hyprctl eval` prints `ok` and returns no value. `hyprctl repl '<lua>'`
  returns a value, e.g. reading `hl.get_monitors()[i].transform`.
- After rotation, `HDMI-A-2` reports transform 1 and stays at 1024x600 mode
  size. The Quickshell surface resized to 600x1024 (`onWidthChanged` and
  `onHeightChanged` fired, no re-creation), and the bar followed to 28x1024.
  `DP-1` stayed at 3840x2160. The i915 DDB limit from the findings log did not
  trigger, because the transform does not change the scanout mode width.
  `hyprctl configerrors` was empty.
- Restored with the same call and `transform = 0`. The panel came back at
  1024x600 at `1920,0`, and the surface followed back.
- A runtime `hl.monitor` call is overwritten by the next `hyprctl reload`,
  which re-reads `monitors.lua`. gjetr has to re-apply the Layout orientation
  after a reload, or accept falling back to the configured orientation.

## 4. Touch following rotation: unverified

This could not be tested without someone at the panel. The digitiser is bound
with `hl.device({ name = ..., output = "HDMI-A-2" })` in `input.lua`. With an
output binding, Hyprland normally maps touch through the output's transform,
but nobody has confirmed that here. The Lua stubs also expose a per-device
`transform` field and an `input.touchdevice.transform` option, which is the
fallback if taps land rotated. Check this on the panel as part of T09.
