# T02 acceptance: plugin skeleton on the panel

Date: 2026-09-13. Installed by symlinking the repo to
`~/.config/omarchy/plugins/nytafar.gjetr`, then
`omarchy-shell shell rescanPlugins` and `omarchy plugin enable nytafar.gjetr`
(which records the id in `shell.json` `plugins[]`).

## Verified on HDMI-A-2

| Check | Evidence |
|---|---|
| Surface on the Display, full output | `hyprctl layers`: `gjetr` 1024x600 at `1920,0` |
| Layer Bottom | `gjetr` at level 1; `omarchy-background` at 0, `omarchy-bar` at 2 |
| No keyboard focus | `WlrKeyboardFocus.None`; active window stayed on DP-1 |
| Black background | `grim -o HDMI-A-2`: black surface, muted placeholder text |
| Bar inset | `omarchy-shell nytafar.gjetr state`: bar `right` 28, content `{x:0,y:0,width:996,height:600}` |
| Hotplug | `hl.monitor({output="HDMI-A-2", disabled=true})`: journal `display HDMI-A-2 absent`, `surface unregistered`, IPC `displayPresent:false`. Re-enabled: `display HDMI-A-2 present`, `surface registered`, same geometry, screenshot renders again |
| Logs | `journalctl --user` lines tagged `[gjetr]`; no QML warnings from gjetr |

The monitor state was restored after the hotplug test (1024x600 at
`1920,0`, transform 0, enabled). DP-1 stayed at 3840x2160 throughout.

## Learned

- A runtime `hl.monitor` rule merges into the output's existing rule.
  `disabled = true` persisted through a later call that left `disabled`
  unset, and only `disabled = false` re-enabled the output. T09 must write
  every field it relies on, and reset what it changed.
- `qmllint` (`/usr/lib/qt6/bin/qmllint`, not on `PATH`) reports only
  `PanelWindow is not creatable`, an artefact of Quickshell's qmltypes.

## Not verified

- Touch on the surface. Nobody was at the panel.
- The inset with a third-party `kind: bar` plugin that exposes no `barSize`.
  In that case the service falls back to `Style.bar` sizes and
  `shell.barConfig.position`.
