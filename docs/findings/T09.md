# T09 acceptance: Deck, tabs, swipe, badges, rotation

Date: 2026-09-13. Hyprland 0.56.2 (Lua config), Quickshell 0.3.1. Fake herdr
and a temporary Config in `/tmp`, read through IPC `useConfigDir`; the
user's `~/.config/gjetr` and `monitors.lua` were not touched.

## What landed

- `lib/DeckPolicy.js`: which Layouts a Display offers (`rotatable` offers
  all; a fixed Display skips the other orientation and keeps all if none
  fits), the active Layout, `hyprctl -j monitors` parsing, the transform for
  an orientation, the tab edge and rectangle, the content inset, the swipe
  step and the tab badges.
- `lib/OverrideModel.js`: `displays.<output>.layout` keeps the active Layout.
  Choosing the Display's first available Layout removes the Override. Old
  state files still read.
- `lib/CommandPolicy.js`: `hyprctl -j monitors` and
  `hyprctl eval 'hl.monitor({ output, mode = "preferred", position = "XxY", scale, transform })'`
  with every value allowlisted.
- `DeckTabs.qml`: tabs along a short edge, labels rotated on side edges, the
  active tab marked in accent, an urgent badge with the Attention count on
  tabs not shown.
- `DeckSurface.qml`: tab bar and content inset; a swipe overlay with a
  sideways-only `DragHandler` that holds a passive grab until it moves, so
  taps and vertical list scrolls pass through.
- `Service.qml`: Deck state, `selectLayout`, `swipeLayout`, rotation on
  Layout, Config and hotplug changes (coalesced), and again 500 ms after
  Hyprland's `configreloaded`. IPC `selectLayout`, `nextLayout`,
  `previousLayout`; `state().deck`.
- `background = "wallpaper"`: the surface is left clear, and it sits on the
  Bottom layer just above `omarchy-background`, so the Omarchy wallpaper shows.
  `#aarrggbb` tints it. That was simple, so M12 is covered.

## Choices

| Choice | Why |
|---|---|
| Tabs opposite the bar when the bar is on a short edge; otherwise left (landscape) or top (portrait) | The bar is on the right here, so tabs go left in landscape. In portrait the bar runs along a long edge, so tabs go top |
| Swipe is always horizontal, towards the left = next, no wrap | The Agent List scrolls vertically; a sideways swipe never competes with it. Needs 80 px and 1.5x more sideways than vertical travel |
| A quarter turn flips the transform's lowest bit (0↔1, 2↔3) | Keeps an upside-down or flipped mounting's sense |
| Rotation writes mode, position (read back from `hyprctl monitors`), scale and transform | Runtime rules merge per output (T02) |
| A Layout still loading counts as `any` | Otherwise it is skipped, and logged as skipped, for one frame |
| Badges count every Attention Agent on tabs whose Layout has an Agent List | An Agent List contains every Agent |

## Touch

Between IPC checks, someone used the panel after the runtime rotation to
portrait. The journal shows a tap on the `agents` tab rotating the output
(`rotation.requests` went to 4 with no IPC call), then many Card taps,
the `both` tab and the header focus toggle. These are top-edge and header
targets in portrait. That suggests touch follows the runtime transform
(T01 open question), but nobody confirmed where each tap landed.
