# T07 acceptance: Focus behaviour `window`

Date: 2026-09-13. Hyprland 0.56.2 (Lua config), herdr 0.8.2, Quickshell 0.3.1.

## What landed

- `lib/WindowPolicy.js`: `ps` process table and `hyprctl -j clients` to the
  window to focus. A window hosts a client when an interactive `herdr`
  process attached to our socket runs anywhere below the window's pid. The
  most recently focused host wins (lowest `focusHistoryID`), and visible
  windows rank before hidden ones.
- `lib/CommandPolicy.js`: the allowlist of every argv gjetr may start. Three
  shapes today: the `ps` table, `hyprctl -j clients`, and
  `hyprctl dispatch 'hl.dsp.focus({ window = "address:0x…" })'` with a hex
  address. `CommandRunner.qml` refuses anything else and never uses a shell.
- `HerdrConnection.qml` emits `paneFocused` when herdr accepts `pane.focus`.
  In `window` mode the service then looks up and focuses the host window.
- Header toggle: the right end of the Agent List header shows
  `focus herdr|window`. A tap flips it as an Override (accent while it
  differs from Config). IPC `toggleFocus`; `state()` reports `windowFocus`
  and command counters.

## Choices

| Choice | Why |
|---|---|
| Client = `comm` is `herdr` and no subcommand | `foot -e herdr` has `herdr` in its args. `herdr terminal session control <pane>` (obsidian-herdr, live here) is a client of the same server, but focusing Obsidian would not show the pane |
| Named sessions map to `~/.config/herdr/sessions/<name>/herdr.sock` | herdr 0.8 socket layout (research doc 03); session names are held to a safe pattern |
| `--remote` clients never match | They attach to another machine's server |
| One `hl.dsp.focus({ window })` | Focusing a window switches to its workspace and monitor; verified below. A separate workspace dispatch would add a flash |
| Window focus only after herdr accepts the pane focus | A failed pane focus should not drag the desk to a terminal showing the wrong pane |

## Verified live

| Check | Evidence |
|---|---|
| Selection | Live table: one host, `foot -e herdr` (pid 3245060). Obsidian's renderer with `herdr terminal session control w2:pA` was not counted: `candidates: 1` |
| Switch and focus | Active window `zen` on workspace 6; IPC `focus wB:p1` in `window` mode; active window became `foot` `0x5586ee998880` on workspace 1, DP-1 active workspace 6 → 1 |
| herdr mode unchanged | With `focus herdr`, the same IPC call left Hyprland on workspace 6 |
| Override | `toggleFocus` wrote `"focus": "window"` into `agents#0` and removed it again on the way back |
| Commands | 12 started, 0 refused |

## Found on the way

- `toggleFocus` and `cycleSort` returned the value from before the change,
  because the Override binding had not re-evaluated when the function
  returned. Both now return the value they wrote.
- While testing, the focus toggle and Cards were being tapped on the panel
  (focus requests rose with no IPC calls, toggles logged about a second
  apart). That is indirect evidence that touch reaches the new header button.

## Not verified

- Ghostty or `foot --server` hosting herdr, where one process owns several
  windows and every one of them matches. The most recently focused of those
  is chosen, which may not be the window running herdr.
- A named `--session` client live. Covered by node tests only.
